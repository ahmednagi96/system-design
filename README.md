### Idempotent 
1. المشكلة الحقيقية اللي بيحلها (ليه بنحتاجه أصلاً؟)
في عالم الـ APIs، فيه مشكلتين أساسيتين مستحيل تمنعهم من ناحية الشبكة:

مشكلة "الرد التايه" (The Lost ACK Problem): العميل داس "ادفع 1000 جنيه"، الموبايل بعت POST /api/payments للسيرفر. السيرفر خصم الفلوس فعلاً وسجلها في SQL Server، وهو راجع بالرد (200 OK) باقة الإنترنت عند العميل فصلت أو حصل Timeout. تطبيق الموبايل افتكر إن الطلب موصلش، فعمل Automatic Retry وبعت نفس الطلب تاني. من غير Idempotency، العميل هيتخصم منه 2000 جنيه.

مشكلة الضغطة المزدوجة (Race Condition / Double Click): العميل داس على زرار الشراء مرتين ورا بعض في جزء من الثانية، أو خدمة تانية بتكلمك عن طريق Polly Retry Policy وبعتت طلبين في نفس اللحظة لـ 2 Instances مختلفين من الـ ASP.NET Core API ورا الـ Load Balancer.
